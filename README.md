# Electric Vehicle Winter Range — Frontend

Frontend-приложение для работы с электрическими нагрузками автомобиля, влияющими на энергопотребление электромобиля в зимних условиях.

Проект разработан в рамках лабораторных работ по дисциплине «Разработка интернет-приложений».

## Технологии

- React 19
- TypeScript 5.9
- Vite 8
- React Router
- React Bootstrap
- Bootstrap

В лабораторной работе №5 используются mock-данные. Взаимодействие frontend с backend, PostgreSQL и MinIO/S3 на данном этапе не выполняется.

## Запуск проекта

Установка зависимостей:

```bash
npm install
```

Запуск приложения в режиме разработки:

```bash
npm run dev
```

После запуска приложение доступно по адресу:

```text
http://localhost:5173/
```

Проверка исходного кода:

```bash
npm run lint
```

Production-сборка:

```bash
npm run build
```

## Страницы приложения

В системе предусмотрены четыре основные страницы:

1. Лента электрических нагрузок.
2. Добавление электрической нагрузки.
3. Плитка электрических нагрузок.
4. Аутентификация.

В лабораторной работе №5 доступны только страницы **«Лента»** и **«Плитка»**. Пункты **«Добавление»** и **«Вход»** присутствуют в меню, но пока недоступны.

### Лента

URL:

```text
http://localhost:5173/
```

Страница доступна в лабораторной работе №5.

Лента предназначена для просмотра электрических нагрузок автомобиля.

Для каждой нагрузки отображаются:

- название;
- описание;
- категория;
- приоритет;
- потребляемая мощность;
- количество отметок «Нравится»;
- изображение;
- видео.

В лабораторной работе №5 карточки формируются из коллекции mock-объектов без обращения к backend.

### Добавление электрической нагрузки

Целевой маршрут:

```text
/add
```

Страница предусмотрена архитектурой системы, но в лабораторной работе №5 недоступна. Пункт **«Добавление»** в навигационном меню отключён.

Страница предназначена для создателя электрической нагрузки.

На ней предусматривается форма со следующими данными:

- название электрической нагрузки;
- описание;
- категория;
- потребляемая мощность;
- приоритет;
- изображение;
- видео.

В полной версии системы создание нагрузки должно формировать черновик, который затем может быть заполнен и опубликован создателем.

Реализация взаимодействия этой страницы с REST API относится к следующим лабораторным работам.

### Плитка

URL:

```text
http://localhost:5173/tile
```

Страница доступна в лабораторной работе №5.

Плитка отображает электрические нагрузки в виде набора карточек.

Реализованы следующие фильтры:

- поиск по названию;
- выбор категории;
- максимальная потребляемая мощность.

После изменения фильтров автоматически пересчитывается набор отображаемых карточек.

На странице также отображается количество найденных электрических нагрузок.

Кнопка **«Сбросить фильтры»** очищает все установленные условия фильтрации.

### Аутентификация

Целевой маршрут:

```text
/auth
```

Страница предусмотрена архитектурой системы, но в лабораторной работе №5 недоступна. Пункт **«Вход»** в навигационном меню отключён.

Страница предназначена для входа и регистрации создателя электрических нагрузок.

Предусматриваются:

- поле имени пользователя;
- поле пароля;
- действие входа;
- действие регистрации.

В полной версии системы после успешной аутентификации пользователь получает JWT-токен, используемый для выполнения защищённых запросов к REST API.

Подключение этой страницы к backend относится к следующим лабораторным работам.

## Навигация

В нижнем навигационном меню расположены четыре пункта:

- **Лента** — доступна;
- **Добавление** — недоступна в ЛР5;
- **Плитка** — доступна;
- **Вход** — недоступна в ЛР5.

Для доступных страниц используется клиентская маршрутизация React Router.

В лабораторной работе №5 маршруты для страниц добавления и аутентификации не активированы.

## Mock-данные

Тестовые данные находятся в файле:

```text
src/shared/data/mockLoads.ts
```

В ЛР5 mock-массив временно заменяет получение данных от REST API.

Описание структуры электрической нагрузки расположено в:

```text
src/entities/electric-car-load/model/types.ts
```

Основные поля объекта:

- `id` — идентификатор;
- `name` — название;
- `description` — описание;
- `category` — категория;
- `power_draw_w` — потребляемая мощность;
- `priority` — приоритет;
- `image_url` — путь к изображению;
- `video_url` — путь к видео;
- `like_count` — количество отметок «Нравится».

## Компонент карточки

Для отображения электрической нагрузки используется компонент:

```text
src/widgets/load-card/LoadCard.tsx
```

Объект электрической нагрузки передаётся компоненту через `props`:

```text
load: ElectricCarLoad
```

Один компонент `LoadCard` повторно используется для отображения разных объектов коллекции.

## Изображение и видео по умолчанию

Если у электрической нагрузки отсутствует собственное изображение, используется:

```text
/public/default.jpg
```

Если отсутствует видео, используется:

```text
/public/default.mp4
```

Для изображения также реализована обработка ошибки загрузки. Если исходный файл загрузить не удалось, компонент автоматически переключается на `default.jpg`.

## Фильтрация

Фильтрация реализована на странице плитки.

Используются три состояния:

- `search` — строка поиска;
- `category` — выбранная категория;
- `maxPower` — максимальная мощность.

Для получения результата применяется метод `filter`.

Электрическая нагрузка отображается только при одновременном выполнении всех заданных условий.

Для формирования React-компонентов карточек из полученного массива используется метод `map`.

## React Hooks

### useState

`useState` используется для хранения текущих значений фильтров:

```text
search
category
maxPower
```

При изменении состояния компонент повторно рендерится и набор отображаемых электрических нагрузок пересчитывается.

### useEffect

`useEffect` используется на странице плитки для установки заголовка документа после рендеринга компонента:

```text
Плитка электрических нагрузок
```

## Маршрутизация

Маршрутизация реализована с помощью `react-router-dom`.

Доступные в ЛР5 маршруты:

```text
/       — Лента
/tile   — Плитка
```

При переходе между страницами React Router переключает отображаемые компоненты без загрузки отдельных HTML-документов.

Неизвестный маршрут перенаправляется на страницу ленты.
